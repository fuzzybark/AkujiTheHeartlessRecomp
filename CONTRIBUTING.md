# Contributing to Akuji Recomp

Thank you for your interest in contributing to **Akuji the Heartless Recomp**! We welcome contributions that improve game stability, fix rendering or audio discrepancies, enhance documentation, or expand platform compatibility.

---

## 1. Code of Conduct

We are committed to providing a friendly, respectful, and harassment-free environment for all contributors. Please communicate with courtesy and respect in all issue discussions, pull requests, and project forums.

---

## 2. Essential Clean-Room & Legal Rules

### Absolute Requirements
* **No Copyrighted Game Assets:** Never submit pull requests that include proprietary game assets, level data, textures, models, sound effects, music, or commercial disc images (`.bin`, `.cue`, `.iso`, `.chd`).
* **No Generated Game Code:** Never commit or submit pull requests containing files inside `generated/` (`SLUS_007.15_dispatch.c`, `overlays_static_*.c`, etc.). To protect the project from copyright liability as an unauthorized derivative work, translated game C code must remain strictly local and generated by users from their own disc.
* **No Proprietary Retail BIOS Code:** Do not commit retail PlayStation BIOS dumps (`SCPH-1001.bin`, etc.) or reverse-engineered code derived directly from proprietary binaries. All BIOS modifications must target the clean-room OpenBIOS implementation.
* **Respect Licensing Constraints:** The project adapter code is MIT licensed, but when combined with the static recompiler runtime (`psxrecomp`), binary builds are governed by the PolyForm Noncommercial License 1.0.0. No commercial exploitation is allowed.

---

## 3. Scope of Contributions

We actively accept:
* Bug fixes for native runtime crashes, memory leaks, or rendering glitches.
* Accurate symbol naming and documentation for internal game functions in `symbols.toml` and `seeds/ghidra_funcs.txt`.
* Performance optimizations in hardware simulation loops (GPU, SPU, CD-ROM).
* Enhancements to the recomp-ui launcher, gamepad configuration, and accessibility options.
* Improvements to build scripts, documentation, and continuous integration workflows.

---

## 4. Submitting a Pull Request

1. **Fork the Repository:** Create your own fork of the repository on GitHub.
2. **Create a Feature Branch:** Branch off from `master` (or the designated development branch):
   ```bash
   git checkout -b fix/rendering-glitch
   ```
3. **Keep Changes Focused:** Ensure your pull request addresses a single, specific issue. Avoid mixing unrelated refactoring with functional bug fixes.
4. **Test Thoroughly:** Verify that the project builds in Release mode without compiler warnings and that gameplay remains stable without regressions.
5. **Commit Messages:** Use clear, descriptive commit messages following the Conventional Commits specification (e.g. `fix(gpu): resolve sub-pixel clipping artifact on Sanctuary gates`).
6. **Submit PR:** Open a pull request against the upstream repository with a detailed summary of your changes, reproduction steps, and testing results.
